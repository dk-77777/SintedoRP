# Inicialização do ambiente Conecta SINTEDORP

Use o checkout existente em /workspace/SintedoRP e preserve alterações do usuário. O ambiente já é isolado; não crie worktrees salvo solicitação explícita. A autorização atual permite continuar o desenvolvimento sem pedir aprovação a cada etapa.

Esta é a versão funcional de desenvolvimento: PostgreSQL, Better Auth, Mailpit e operações com autorização no servidor. Use somente dados de teste enquanto as definições institucionais estiverem pendentes. A demonstração antiga fica em /demo e nunca deve ser usada como prova de autenticação real.

1. Confirme Node.js 24 e disponibilidade do daemon Docker. O install_script reproduz instalação por lockfile, serviços locais, migrações, build, tipos e testes de documentos/datas. Se faltarem dependências/artefatos ou o código tiver mudado, use scripts/cloud-install.sh. Não altere manifests ou lockfile somente para inicializar.
2. Execute npm run services para reutilizar/iniciar os containers conecta-sintedorp-db e conecta-sintedorp-mail. O script preserva arquivos privados e dados existentes. PostgreSQL usa /workspace/.state/sintedorp/postgres; o checkout contém .env.local e .local com credenciais locais privadas. Não imprima esses arquivos ou variáveis. Não use esses serviços para produção externa.
3. Execute npm run db:migrate. O runner verifica checksum, trava concorrência e aplica somente migrações pendentes, em transação. A versão atual possui quatro migrações, incluindo 004-experience-closure.sql. Nunca altere migração aplicada nem reinicialize banco com dados para resolver erro de instalação.
4. Verifique uma porta livre. A padrão é 3000; não encerre serviços desconhecidos. Se precisar de outra porta, substitua a origem somente no processo: BETTER_AUTH_URL=http://localhost:3001 npm run start -- --port 3001. A origem usada no navegador deve coincidir exatamente. Mantenha a sessão do executor; processos não sobrevivem necessariamente à publicação/restauração do ambiente.
5. Verifique localmente HTTP 200 e status ready em /api/health; confirme /, /vagas e /entrar no navegador, com interface carregada e sem exceções JavaScript. Porta/PID sozinho não prova prontidão. Não publique links de localhost no relatório para o usuário.
6. Crie conta e confirme o e-mail na caixa local Mailpit (porta 8025). Conceda permissões sindicais somente a uma conta existente e verificada pelo procedimento npm run admin:grant -- email ADMIN|MODERATOR|ANALYST. Não crie senha padrão, não promova uma conta do usuário sem instrução e não use o perfil sindical de /demo para operações reais.
7. Para editar, use npm run dev com a porta/origem escolhidas. Para validar mudanças relevantes: npm run typecheck, npm run build, npm run test:server, npm run test:live e npm run test:e2e. A suíte real usa banco temporário local e porta 3100; a demonstração usa 3200. Chromium do sistema é detectado, ou configure PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH. Preserve TLS, checksums e arquivos do usuário.

Leituras: README.md, docs/ETAPAS-04-A-07-RESULTADOS.md, docs/ETAPA-08-RESULTADOS.md, docs/ETAPA-09-RESULTADOS.md, docs/PUBLICACAO.md, docs/HOSPEDAGEM-GRATUITA.md e docs/CRIAR-CONTAS-E-PUBLICAR.md. O usuário informou que ainda não criou os projetos Vercel/Supabase. A opção gratuita recomendada para apresentação acadêmica é Vercel + Supabase, sujeita às condições atuais dos planos; não há implantação ou credenciais externas configuradas. DATABASE_POOL_MAX permite limitar de 1 a 12 conexões por instância; use 2 como ponto inicial em serverless. A autenticação limita requisições por contador compartilhado quando não há proxy confiável configurado; configure o proxy institucional antes de uso público. Não invente contatos, pisos salariais, política LGPD ou resultados de consultas externas. APIs de CPF/CNPJ e SMTP externo não estão configurados.

Para preparar configuração externa, npm run deploy:prepare cria .local/production.env e .local/migration.env sem credenciais, com permissão 600 e sem sobrescrever arquivos. Não os imprima nem os compartilhe. npm run deploy:check usa apenas variáveis explicitamente injetadas e não lê .env.local; sem valores externos ele deve falhar, o que não impede o desenvolvimento local. Use --connect somente depois de configurar os serviços: confere banco/checksums por leitura e autenticação SMTP sem mensagem. Testes específicos dessas ferramentas: npm run test:server e npm run test:live -- --grep 'Implantação:'. Não execute serviços locais contra produção nem use o pooler de transação nas migrações. Siga o guia para injeção segura das variáveis e conexão de sessão.

O rascunho salva install_script e start_skill; salvar não executa scripts nem publica o ambiente. O produto controla a revisão, o salvamento e a publicação da configuração/snapshot. O código do projeto foi criado no checkout de um repositório inicialmente vazio; não houve commit/push ou publicação pública.
